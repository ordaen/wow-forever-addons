# Bench

Generated by `scripts/bench_save.lua` from `report.json` (every round, computed from `results/`, one file per
round: the history); the design site's Bench page shows every round. This is the newest.

- **Lua:** the call's own time (debugprofilestop). Below 0.01 ms it is timer noise: no factor.
- **Frame:** from the call's start to the next frame, the work WoW defers to drawing included, minus the block's idle frame (each block starts with one). "≈ idle" is within the idle frames' own spread (p95 above median): no factor.
- **Engine / backend:** the framework row's Lua time on the stub backend (the engine alone) and the rest (the drawing backend's share). Lua only: the stub draws nothing, so its frame times mean nothing. The stub's empty calls (about 0.1 ms per 1000) count as engine time, so the backend's share reads slightly low.
- **Net KB:** Lua heap growth per call (negative: a call that frees, such as a table shrinking). No Lua time holds collector work: the collector is stopped right before every timed call. Frame time can, where WoW stepped the collector between frames: those frame values carry ᵍ, and the round lists in how many of the series' frames (a few: the median likely holds, the p95 likely doesn't). What collecting a scenario's garbage costs is a bench of its own. **Kept KB** (make rows): what stays after a full collection. The Lua heap only: WoW frames' own memory is invisible to every side. **Engine net KB / Engine kept KB:** the same on the stub backend (the engine alone, plus the stub's bookkeeping); the rest is the drawing backend's.
- **¹** a single sample (a first opening, a hand make): its frame time is one frame's, not a median.
- **Built as players run it:** every round is on the bench profile (release stripping, the bench's dev hooks kept) with the debug addon disabled; bench_save refuses any other.
- **Engine / backend, read with care:** the stub run touches less memory, so the engine runs with warmer caches there and the backend's share reads slightly high. Hand-written drawing leaves its text layout to WoW's drawing, so compare the backend with best's frame column, not its Lua column.
- **Change:** against the newest earlier comparable round (clean builds, the same plan shape: the same series with the same calls, since what runs before a row is part of its conditions); an improvement or a regression is a change of 10% or more beyond the noise (the row's own spread, p95 above median, in either round; for frame also the idle spread); single samples (¹) and frame values with collector work (ᵍ) in either round never count. Same graphics quality and spot in the world (zone and subzone) only; stand in the same place facing the same way, since the world drawn is in every frame time.

Reading it:

- **One /obench:** a cold block first (the large grid's first open on every side while the session is fresh), then the whole plan measured; each series' first calls stay out of its numbers. `/obench variants` adds the framework's variants.
- **open, close, first open:** each side its own way: the framework mounts from its pools and unmounts; hand code shows and hides the frames it made once, or rebuilds and drops the state it has instead of frames. **first open** is every side's first opening in a fresh session.
- **framework-naive** (variants rounds): grid and ticker written as code reads without the build's lifting and hoisting: new tables and a new slot function every call. Its rows include lost skipping (a new slot function re-renders the child), not only allocation.
- **chain, diamond, cascade:** there for their checks (each watch runs once per change, no stale reads): a few calls, not a timing series.
- **grid steady:** the grid on screen with nothing changing. "≈ idle" means drawing it adds nothing to the main thread's frame (what an addon costs players' frames); WoW's render threads can still do work their slack hides, so not that drawing is free.
- **Same as baseline:** after each block, what every side ended on (its texts and where their glyphs sit; the textures' rects where the scenario draws shapes; a checksum of every watch's result where nothing is drawn) is compared with the baseline's. Both ran the same seeded actions, so a side that skipped work or drew something else fails, whatever its time.
- **deep, value through 100 levels:** the framework hands the value down as an attribute through every level; hand code sets the one text directly. Intended: it shows what passing attributes costs.
- **rows, filter, tooltip, sections:** the framework releases the nodes of what goes away and takes them (from its pools) for what comes back; hand code hides and shows frames it keeps. That difference is in their rows.
- **hover:** the bench calls the cells' frames' OnLeave and OnEnter scripts; WoW finding the frame under the cursor (hit testing) is the same on every side and isn't measured. No engine side: the stub draws no frames.
- **scheduler:** two ways to start the engine's flush, 1000 minimal schedulers each (a row's ms is µs per scheduler). Framework column: the engine's way, the OnUpdate attached on a frame's first write and removed by the flush. Best column: the proposed way, the OnUpdate always attached and returning when nothing is pending. Writes are in the Lua column; the OnUpdates (attach's removal, always's call every frame) only in the frame column.
