# Bench

Generated by `scripts/bench_save.lua` from the newest round in `results/` (one file per round: the history).
Each scenario (`addons/OrdaenBench`) on the framework, by hand at its best (`baseline/`) and, where it differs,
as a typical addon writes it (`typical/`). Medians in ms, per call or per frame as the metric says:

- **Lua:** the step's own time (debugprofilestop). It misses what WoW defers to drawing.
- **Frame:** from one frame to the next, the deferred work included, minus the idle frame (the `idle` rows:
  a frame with nothing to do, measured at the start and end of the round).
- **KB:** Lua heap growth per call, the garbage players pay for later.
- **Change:** the framework's Lua and frame medians against the round before.

Reading it:

- **grid close and open+close:** the framework unmounts and mounts again (the MVP has no hidden attribute);
  hand code hides and shows. Both are real costs, not the same operation, so they have no factor.
- **grid steady:** the grid on screen with nothing changing: what drawing it costs every frame.
- **make:** hand code always makes its frames new (one round per /reload); the framework's pools may already
  hold frames from an earlier scenario of the same round (the large grid reuses the small grid's).
- **deep, value through 100 levels:** the framework hands the value down as an attribute through every level;
  hand code sets the one text directly. Intended: it shows what passing attributes costs.
